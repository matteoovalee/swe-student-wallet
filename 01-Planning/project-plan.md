The same rule applies to every member. The contribution table in the report is built from these issues and from the pull requests.

## How we work

We use Scrum in a simple form: one-week sprints. Every sprint has a goal and a milestone on GitHub. Tasks are issues on the project board (Todo, In Progress, Done). Every task gets its own branch and pull request, and the pull request says which issue it closes. At the end of a sprint we tag the version on main.

We do not hold separate meetings. We coordinate in the group chat, and the work itself is discussed in the issues and in the pull request reviews. At the end of each sprint Matteo writes a short review in `sprint-log.md`: what was planned, what was done, what we change.

## Main activities

1. Choose the system and write down why (Smart Financial, student wallet in two currencies).
2. Collect requirements: user stories, functional and non-functional requirements, a survey with international students.
3. Model: use case diagram and descriptions, architecture, ER diagram.
4. Design the screens: wireframes in Figma.
5. Build the prototype in Python with Streamlit.
6. Test: test plan, test cases, test results, traceability matrix.
7. Write the report and prepare the presentation.
